## 2026-10-28 - [Global Rate Limit DoS via Native-First IP Extraction]
**Vulnerability:** Global Rate Limit Denial of Service when running behind a reverse proxy (`trustProxy=true`).
**Learning:** In Hono, `getConnInfo(c)` successfully returns the TCP socket's remote IP address. When running behind a reverse proxy (e.g. Caddy), the socket's remote IP is always the proxy's IP. Previous implementations used `let ip = nativeIp; if (!ip && trustProxy) { ... }`, intending to fallback to proxy headers only if `nativeIp` was missing. However, because `nativeIp` successfully returned the proxy's IP, `!ip` was always false, causing the `x-forwarded-for` block to never run. This grouped all proxy-routed traffic under a single IP bucket (the proxy's IP), effectively turning a per-IP rate limit into a global server rate limit, causing severe denial of service during normal traffic loads.
**Prevention:** When `trustProxy` is true, ALWAYS prioritize extracting the IP from the `x-forwarded-for` header FIRST. Only fallback to `nativeIp` if proxy headers are completely absent. Additionally, testing should include proxy simulation (e.g., direct node hits vs proxied hits) to verify bucket segregation.
