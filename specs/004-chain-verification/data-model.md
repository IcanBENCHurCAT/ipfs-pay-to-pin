# Data Model: Chain Verification Indexer

## Entities

### 1. Transaction Record
Represents an on-chain Algorand transaction that has been successfully verified and processed by the gateway. This is persisted to prevent double-spend attacks.

**Fields**:
- `txn_id` (String): The unique Algorand transaction ID. **(Primary Key)**
- `sender` (String): The Algorand wallet address that sent the payment.
- `receiver` (String): The Algorand escrow address that received the payment.
- `amount` (Integer): The amount paid in microALGOs.
- `reference_id` (String): The extracted reference hash from the transaction note field.
- `timestamp` (DateTime): The time the transaction was processed by the gateway.

**Validation Rules**:
- `txn_id` must be exactly 52 characters (standard Algorand base32 encoding).
- `amount` must be > 0.
- `receiver` must match the configured gateway escrow address.

### 2. Verification Challenge
Represents an internal, pending file upload that is waiting for an on-chain payment.

**Fields**:
- `reference_id` (String): A unique identifier generated by the gateway for the challenge. **(Primary Key)**
- `expected_amount` (Integer): The calculated microALGO fee for the requested file size.
- `escrow_address` (String): The destination address the user is expected to pay.
- `status` (Enum: `PENDING`, `VERIFIED`, `REJECTED`, `EXPIRED`): The current state of the challenge.
- `expires_at` (DateTime): When the challenge is no longer valid.

**State Transitions**:
- `PENDING` -> `VERIFIED`: When a valid `Transaction Record` is found on-chain that matches the `reference_id` and `expected_amount`.
- `PENDING` -> `REJECTED`: When a submitted transaction ID is invalid, is a double-spend, or has an insufficient amount.
- `PENDING` -> `EXPIRED`: If the `expires_at` timestamp passes without successful verification.
